# Проверка о чужие реализации

Тест на записанных байтах ловит ошибку в кадре, но не в понимании протокола:
свой разбор согласится сам с собой при любой ошибке, и обе стороны будут
одинаково неправы. Поэтому здесь стоят чужие серверы, и клиент ходит через них
до своего веб-сервера.

```bash
./run.sh            # все протоколы
./run.sh socks5     # один
```

На Windows — `scripts\interop\run.cmd` из корня проекта: он сам найдёт `bash`
внутри Git for Windows.

Нужны `docker`, `openssl` и `curl`. Из `scripts/check.sh` не зовётся: образы
тянутся долго, а падение сети выглядело бы падением коммита.

---

## Отчёт

Весь вывод дублируется в `report.txt` рядом со скриптом, путь печатается
последней строкой. Смотреть надо его: там не только какой протокол не прошёл,
но и что ответил его сервер.

Проверка не останавливается на первом отказе: смысл прогона — увидеть все
протоколы разом.

---

## Что происходит

1. Самоподписанный сертификат для Hysteria 2 — один раз (`tls/` в
   `.gitignore`).
2. `docker compose up` поднимает серверы и `target` — свой `nginx`, отвечающий
   строкой `penguin-interop-ok`. Свой, а не сайт в сети: падение чужого сайта
   не должно выглядеть падением протокола.
3. На каждый протокол пишется профиль и запускается `penguin socks
   --no-rules`. Без `--no-rules` маршрутизация была бы лишней переменной.
4. `curl --socks5-hostname` идёт до `target` **по имени**. Имя разрешает
   сервер на той стороне, и это часть проверки: `target` есть только в сети
   `docker`.

Настройки пишутся во временный каталог: проверка не трогает профили того, кто
её запустил.

---

## Чего здесь нет

- **UDP** — готовой утилиты, которая ходит по UDP через SOCKS5, нет, а своя
  проверяла бы протокол его же кодом.
- **Живой прогон** — на машине, где писалась проверка, нет docker. Сценарии
  сверены чтением документации образов, а не работой; первый запуск скорее
  всего потребует правки.
- **ShadowsocksR** — готового образа сервера не нашлось.
- **Проверка отказа** — неверный пароль обязан давать `AuthRejected`, а не
  повторы. Отдельный сценарий: те же серверы, испорченный пароль, ожидаемый
  исход — быстрая ошибка.
