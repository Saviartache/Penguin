# Проверка о чужие реализации

Тест на записанных байтах ловит ошибку в кадре. Ошибку в **понимании**
протокола он не ловит: свой разбор согласится сам с собой при любой ошибке в
номерах и порядке полей, и обе стороны будут одинаково неправы.

Поэтому здесь стоят эталонные серверы — чужие, написанные не нами, — и клиент
ходит через них до своего же веб-сервера.

```bash
./run.sh            # все протоколы
./run.sh socks5     # один
```

Нужны `docker`, `openssl` и `curl`; для `ssh` ещё `ssh-keyscan`
(ключ хоста рождается вместе с образом, и заранее его не знает никто). Из `scripts/check.sh` не зовётся: образы
тянутся долго, а падение сети выглядело бы падением коммита.

## Что происходит

1. Самоподписанный сертификат для Hysteria 2 — один раз, дальше берётся
   готовый (`tls/` в `.gitignore`).
2. `docker compose up` поднимает серверы и `target` — свой `nginx`, отвечающий
   строкой `penguin-interop-ok`. Свой, а не сайт в сети: проверяется протокол,
   и падение чужого сайта не должно выглядеть падением протокола.
3. На каждый протокол пишется профиль и запускается
   `penguin socks --no-rules`. `--no-rules` обязателен: маршрутизация в этой
   проверке — лишняя переменная.
4. `curl --socks5-hostname` идёт до `target` **по имени**. Имя разрешает
   сервер на той стороне, и это часть проверки: протокол, разрешающий имя у
   себя, обломается здесь — `target` есть только в сети `docker`.

Настройки пишутся во временный каталог, а не в настоящие: проверка не имеет
права трогать профили того, кто её запустил. Подменяется не путь внутри
клиента, а то, откуда он его берёт, — переменные среды системы.

## Чего здесь пока нет

**UDP.** Готовой утилиты, которая ходит по UDP через SOCKS5, нет, а писать
свою — значит проверять протокол собственным кодом, то есть ровно тем, чему
эта проверка не верит. Появится вместе с первым протоколом, где UDP — главное
(`plan.md`, фаза 7).

**ShadowsocksR.** Готового образа с сервером SSR не нашлось: ни sing-box,
ни mihomo его входящим не умеют, а собирать свой из мёртвого Python
значило бы тянуть в проверку отдельный проект со своим сроком жизни.
Крейт сверен чтением двух независимых реализаций и записанными байтами,
а не живым сервером, — это слабее, и так и сказано.

**Проверка отказа.** Неверный пароль обязан давать `AuthRejected`, а не
бесконечные повторы. Отдельный сценарий: серверы для него те же, профиль —
с испорченным паролем, ожидаемый исход — быстрая ошибка, а не таймаут.
